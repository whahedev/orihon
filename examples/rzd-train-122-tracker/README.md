# РЖД Multi-Train Tracker · Route Search + Active Trains

Приложение работает без API-ключей.

## Главное изменение

Основной выбор поезда теперь устроен как обычный поиск РЖД:

```text
Откуда: [Москва]
Куда:   [Сочи]
Дата:   [17.08.2026]

[Найти поезда]
```

Пользователь больше не обязан знать номер поезда заранее.

После поиска приложение показывает:

- доступные даты;
- номера подходящих поездов;
- время отправления от выбранной станции;
- время прибытия на выбранную станцию назначения;
- полный маршрут состава;
- статус `СЕЙЧАС В ПУТИ` или `ОТПРАВИТСЯ`.

Клик по поезду переводит карту в режим отслеживания выбранного состава.

## Прошлые даты

Backend автоматически проверяет до 4 предыдущих дат.

Прошлая дата показывается **только если хотя бы один поезд этой даты всё ещё
находится между начальной и конечной станцией своего полного маршрута**.

Например:

```text
17 авг. · сегодня
16 авг. · ещё в пути
15 авг.          <-- не показывается, если поезд уже прибыл
```

Это позволяет выбрать поезд, который отправился 1–4 дня назад, но всё ещё
находится в пути.

Завершённые рейсы в интерфейс отслеживания не попадают.

## Подсказки станций

При вводе `Откуда` и `Куда` frontend обращается к публичному suggest-источнику
веб-версии расписаний:

```text
/api/trains/suggest?q=Москва
```

Подсказка содержит название и код пункта (`c...` или `s...`). Если пользователь
выбирает подсказку, `fromId/toId` автоматически передаются в публичный поиск
расписаний.

Если suggest временно недоступен, поиск всё равно пробует работать по названию.

## Источник расписания

Ключ не требуется.

Используются публичные страницы:

```text
https://rasp.yandex.ru/search/train/
https://rasp.yandex.ru/thread/...
https://rasp.yandex.ru/train/...
```

Результаты нормализуются в собственную модель `TrainRun` и кэшируются локально.

## Все поезда в пути

Слой включён автоматически сразу после запуска:

```text
Все поезда: ВКЛ
```

Сервер параллельно строит индекс активных поездов:

1. открывает публичную страницу ж/д расписаний;
2. получает ссылки на страницы крупных железнодорожных узлов;
3. читает табло этих узлов за сегодня и предыдущие дни;
4. извлекает `thread` поездов;
5. загружает полный маршрут каждого обнаруженного состава;
6. оставляет только рейсы:

```text
departure <= now < arrival
```

7. определяет текущий перегон;
8. получает координаты станций из OpenStreetMap;
9. рассчитывает положение поезда;
10. сохраняет индекс в:

```text
train-cache/active-index.json
```

Frontend обновляет слой автоматически.

### Точность массового слоя

Для уже построенного конкретного маршрута используется его настоящая
железнодорожная геометрия.

Для большого количества ещё не открывавшихся поездов первоначальная позиция
может рассчитываться между координатами текущих соседних станций. Это позволяет
показать много составов без построения сотен тяжёлых OSM-графов одновременно.

После выбора конкретного поезда приложение строит его полноценный маршрут по
рельсам.

### Ограничение охвата

Публичный источник не предоставляет документированный endpoint:

```text
GET /all-trains-currently-running-in-russia
```

Поэтому массовый слой является автоматическим индексом поездов, обнаруженных
через публичные табло крупных узлов. Это намного шире прежнего
`local-catalog`, но технически нельзя гарантировать 100% всех поездов сети РЖД.

В UI выводится количество обнаруженных активных поездов и количество
проиндексированных узлов.

## Железнодорожный маршрут выбранного поезда

При выборе состава:

1. ищется OSM relation:

```text
type=route
route=train
ref=<номер поезда>
```

2. если relation найдена — используется её геометрия;
3. иначе станции сопоставляются с OpenStreetMap;
4. через Overpass загружается `railway=rail`;
5. строится A* маршрут между остановками;
6. результат кэшируется.

121В сохраняет встроенный проверенный fallback:

```text
OSM relation 17137928
37 перегонов
2353.82 км
```

## Фактическое движение РЖД

Экспериментальный адаптер фактического движения РЖД сохранён для 121В.

Массовый слой **не делает** отдельный запрос факта РЖД для каждого поезда —
иначе недокументированный сервис пришлось бы опрашивать сотнями запросов.

Поэтому:

```text
массовый слой -> расписание / оценочное положение
выбранный 121В -> возможна корректировка по факту РЖД
выбранный другой поезд -> расписание + точная OSM-геометрия
```

## API

### Подсказки станций

```text
GET /api/trains/suggest?q=Санкт
```

### Поиск откуда → куда

```text
GET /api/trains/search-route?from=Москва&to=Сочи&date=2026-08-17&lookback=4
```

При наличии кодов подсказок:

```text
GET /api/trains/search-route?from=Москва&fromId=c213&to=Сочи&toId=s9613034&date=2026-08-17&lookback=4
```

Ответ сгруппирован по доступным датам:

```json
{
  "groups": [
    {
      "date": "2026-08-17",
      "isToday": true,
      "candidates": []
    },
    {
      "date": "2026-08-16",
      "isPast": true,
      "candidates": [
        {
          "number": "225А",
          "activeNow": true
        }
      ]
    }
  ]
}
```

Если все поезда прошлой даты уже прибыли, группы для этой даты в ответе нет.

### Старый поиск по номеру

Оставлен для совместимости:

```text
GET /api/trains/search?number=121В&date=2026-08-16
```

### TrainRun

```text
GET /api/trains/run?runId=<runId>
```

### OSM-маршрут выбранного поезда

```text
GET /api/trains/route?runId=<runId>
```

### Все обнаруженные активные поезда

```text
GET /api/trains/active
```

Принудительно обновить индекс:

```text
GET /api/trains/active?refresh=1
```

### Статус провайдеров

```text
GET /api/trains/status
```

## Запуск Windows

```text
start.cmd
```

Открыть:

```text
http://127.0.0.1:8788
```

`start.cmd` остаётся ASCII + CRLF и не содержит `chcp` или русских `echo`,
поэтому исправленная версия не должна выдавать ошибки вида:

```text
'ho.' is not recognized...
'ANDEX_RASP_API_KEY' is not recognized...
```

## Runtime cache

Автоматически создаётся:

```text
train-cache/
  runs.json
  active-index.json
  routes/
  osm-relations/
```

Для обновления глобального индекса можно удалить `train-cache/active-index.json`
или вызвать `/api/trains/active?refresh=1`.

## Проверки этой сборки

Проверено:

- синтаксис `server.mjs`;
- синтаксис `train-catalog.mjs`;
- синтаксис клиентского JS;
- локальный HTTP server;
- `/api/trains/status`;
- `/api/trains/run` для 121В;
- `/api/trains/route` для 121В;
- `/api/trains/active`;
- выбор прошлой даты только для незавершённого поезда на синтетической выдаче;
- скрытие уже прибывшего прошлого рейса.

Из среды сборки нет DNS-доступа к `rasp.yandex.ru`, поэтому живой публичный
поиск должен быть проверен уже на машине пользователя. При этом структура
публичных страниц и URL была дополнительно сверена по актуальным страницам
расписаний.
